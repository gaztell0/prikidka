# Прикидка — калькулятор PERT-оценки

Статический калькулятор трёхточечной оценки задачи: три сценария в часах, результат в часах и в SP. Без фреймворков, зависимостей и сборки — HTML, CSS и ES-модули.

- Прод: https://gaztell0.github.io/prikidka/
- Dev-превью: https://gaztell0.github.io/prikidka/dev/

## Что считает

| Величина | Формула |
| --- | --- |
| Часы | `(O + 4M + P) / 6` |
| SP | `часы / 8` |

- `O` — оптимистичная оценка, `M` — наиболее вероятная, `P` — пессимистичная.
- Допустимый диапазон — от `0,01` до `100 000` ч, не больше двух знаков после запятой; принимаются запятая и точка.
- Обязателен порядок `O ≤ M ≤ P`, иначе поля подсвечиваются ошибкой.
- Пересчёт в SP — соглашение проекта, а не часть PERT. Границы `O…P` не являются доверительным интервалом.

## Локальный запуск

```bash
npm run dev
# http://127.0.0.1:4173
```

`server.js` — минимальный статический сервер с `cache-control: no-store`; он отдаёт только файлы сайта.

## Тесты

```bash
npm test
```

`node --test` проверяет модель и сборщик Pages: 15 тестов модели + 5 тестов сборки. Тесты покрывают формулу, границы диапазона, порядок сценариев, лексику ввода (запятая/точка, точность, мусор), URL-состояние и защиту публикации.

UI-автотестов нет: [qa-matrix.json](qa-matrix.json) — ручной чек-лист (16 pairwise + 28 equivalence-кейсов). Ожидаемые значения из матрицы сверяются с моделью в `model.test.js`, но сам интерфейс проверяется руками.

## Структура

| Файл | Назначение |
| --- | --- |
| `index.html` | Разметка, inline-инициализация темы до отрисовки |
| `style.css` | Светлая/тёмная тема, адаптивная вёрстка |
| `model.js` | Чистая модель: парсинг, валидация, PERT, состояние URL |
| `app.js` | DOM: ввод, ошибки, тема, подсказки, deep links |
| `server.js` | Локальный сервер для разработки |
| `qa-matrix.json` | Ручная матрица UI-проверок |
| `scripts/build-pages.mjs` | Сборка объединённого сайта prod + `/dev` |
| `.github/workflows/ci.yml` | Тесты на push/PR |
| `.github/workflows/pages.yml` | Публикация на GitHub Pages |

## Публикация

Один репозиторий и один Pages-сайт:

- **прод** в корне `/` собирается из `main`;
- **dev-превью** в `/dev/` собирается из `dev`;
- в обоих корнях публикуется `deployment.json` с `environment`, `branch` и `sha`.

Поток:

1. Push или merge в `main` (только через PR — ветка защищена) запускает CI.
2. Успешный CI запускает workflow `Pages`, который берёт последний зелёный CI-пуш каждой ветки.
3. `scripts/build-pages.mjs` проверяет regular-файлы, актуальность `?v=`-хешей и полные SHA, затем собирает `_site`: корень из `main`, `/dev` из `dev` с заголовком `DEV ·`.
4. `actions/deploy-pages` публикует сайт.

Особенности:

- Нужен зелёный CI **обеих** веток: если у `main` или `dev` нет успешного push-рана, деплой пропускается целиком и сайт остаётся прежним.
- `main` защищена: прямые пуши запрещены, изменения — через PR.
- Ветка окружения `github-pages` разрешает деплой только из `main` (workflow запускается на ref `main` даже при триггере из `dev`).
- Кэш сбрасывается вручную: при изменении `style.css`, `app.js` или `model.js` обновите `?v=<sha256-12>` в `index.html`/`app.js`. Сборка упадёт, если хеш не совпадает с файлом.

## Ограничения

- PERT-оценка — экспертный прогноз, а не измерение; уточняйте её по фактическим трудозатратам.
- Поддерживаются современные браузеры: используются ES-модули, `:has()` и `100svh`.
- Внешних зависимостей нет; `npm install` не требуется.
